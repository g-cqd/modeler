# modeler 0.4.0 (from 0.3.0)

A new rule, five false positives fewer, and a TLA+ model that keeps the preconditions the code has (analyzerkit roadmap
0062, 0064). Found running modeler on maintastic, where 29 findings went to 24 under the old rules. analyzerkit is still
`0a13bbf`.

## Flags

none

## Exit codes

`stale-index` is an error by default, so a run that reports one exits 1 without `--strict`.

## Report

The new rule id, `stale-index`. `modeler facts`: effects of kinds `cancel`, `bindIndex` and `useIndex`, reads of
`Task.isCancelled`, calls in conditions marked `isCheck`, and an enum's `predicates` (its Boolean computed properties
and the cases each holds for).

## Configuration

`stale-index` can be disabled or given another severity like any rule.

## Cache

The facts change shape; a cache written by 0.3.0 is not reused (the build identity changes with the version).

## Findings that may appear

- `stale-index`: a local bound from `firstIndex`, `lastIndex`, `index`, `indices`, `startIndex` or `endIndex` of a member
  collection (or from `+`/`-` on one), then an `await`, then a subscript of that member with it, or `remove(at:)`,
  `insert(_:at:)`, `replaceSubrange`, `removeSubrange` or `swapAt`. Actors and global-actor types. The `reentrancy`
  finding on the same line is no longer reported. On maintastic: `ChatMessageListViewModel.refreshMessage(with:)`.

## Findings that may disappear

- `reentrancy` where the code checks again after the `await` in a way 0.3.0 did not see: a condition calling a method of
  the type that reads the member (not itself awaited); a check of a token the method wrote before, when every other
  writer of the member writes it too; `Task.isCancelled` or `try Task.checkCancellation()`, when every other writer
  cancels a task a member holds.
- `lock-gap` in a type whose only `withLock` is on a local or a parameter.
- On maintastic: five (`CreateTicketDialogModel`, `PreviewableImageProvider` twice, `AppCommunication`,
  `AudioFormatConverter`).

## TLA+

A guard on an enum's Boolean computed property (`state.isRecording || state.isPaused`), and a `switch` whose other
cases leave, now narrow the member, so the model has the preconditions the code has. A claimed finding's monitor
starts from the value the claim wrote. On maintastic's `RecordingCoordinator`, TLC's traces started from states the
code refuses; it now finds a real one (`start()` claims `.preparing`, `handleMediaServicesReset()` sets `.idle`,
`start()` overwrites it).
