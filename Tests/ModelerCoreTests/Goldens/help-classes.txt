OVERVIEW: A Mermaid class diagram: types, members, conformance and ownership.

USAGE: modeler classes [<paths> ...] [--config <file>] [--exclude-path <pattern> ...] [--include-regions <list>] [--exclude-regions <list>] [--define <name> ...] [--only <file> ...] [--only-from <file>] [--cache-path <directory>] [--no-cache] [--type <type> ...] [--depth <depth>]

INPUT:
  <paths>                 Swift files or directories to analyze. (default: .)
  --config <file>         Configuration file (default: the tool's configuration
                          file in the current directory, when present).
  --exclude-path <pattern>
                          Leave out the paths matching this pattern
                          (repeatable): a substring, or a glob with *, ? or [.
  --include-regions <list>
                          Regions to treat as first-class code:
                          preview,debug,test,mock,generated,script, or all.
  --exclude-regions <list>
                          Regions to keep out of scope, even under
                          --include-regions all.
  --define <name>         An #if condition to treat as set (repeatable; the
                          compiler's -D).
  --only <file>           Report only findings in this file (repeatable); the
                          whole corpus is still analyzed.
  --only-from <file>      Read --only paths from a file, one per line ('-'
                          reads stdin).

CACHE:
  --cache-path <directory>
                          The facts cache's root directory (default: the tool's
                          directory in the user cache directory).
  --no-cache              Do not read or write the facts cache.

OPTIONS:
  --type <type>           Centre the diagram on this type; repeatable. Without
                          it every type is drawn.
  --depth <depth>         How many edges away from --type to include. (default:
                          1)
  --version               Show the version.
  -h, --help              Show help information.
